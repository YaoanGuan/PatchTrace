# 任务

你将收到一张项目溯源图的 YAML 快照，以及一个已经认领的当前意图。图中的事实（facts）是已经确认的客观结论，意图（intents）是待验证的探索方向。

请只围绕当前意图指定的方向推进，在既有事实的基础上尝试验证它，并把本轮新增的客观结论写回。探索可能成功，也可能失败；无论结果如何，都要给出可复核的结论。

# 输出要求

只返回一个原始 JSON 对象，不要输出任何其它文字，不要使用 Markdown 代码围栏。JSON 必须合法，字符串中的引号与换行必须正确转义。

正常返回：

```json
{"accepted":true,"data":{"description":"..."}}
```

若本轮结论构成对当前意图的明确判决，可以在 `data` 中附加可选字段：

```json
{"accepted":true,"data":{"description":"...","verdict":"support","evidence_ref":"...","target":"..."}}
```

- `verdict`：可选，只能取 `support`（证据支持当前意图）或 `refute`（证据反驳当前意图）。没有明确判决时不要填写。
- `evidence_ref`：可选，指向承载证据的沙箱文件或输出路径。
- `target`：可选，判决针对的图中节点编号；缺省为当前意图，只有已存在的节点才会被采用。

若需要在沙箱中实际执行验证命令，可在 `data` 中附加可选字段，Runner 会替你执行并记录客观结果：

```json
{"accepted":true,"data":{"description":"...","command":"...","workdir":"...","verdict":"support","evidence_ref":"...","target":"..."}}
```

- `command`：可选，交给沙箱执行的完整 shell 命令（应可复现、无破坏性）。
- `workdir`：可选，命令的工作目录；缺省时由沙箱默认目录决定。
- 请在 `description` 中说明这条命令的预期结果（例如“预期返回 200 并进入 eval 分支”）；Runner 会把实际退出码、stdout 与 stderr 追加到客观结论中。

只有在确实应当拒绝任务时才返回：

```json
{"accepted":false,"reason":"policy_refusal"}
```

# 规则

- 先充分探索当前意图再结束；确认该方向无法推进时，也要把尝试过的关键观测和客观结果写清楚。
- `description` 只写本轮新增、且已经确认的客观结论，不要重复图谱快照中已有的事实，不要写计划或猜测。
- 失败、受阻或证据不足同样是有效结论；必须如实说明原因，不得把推测包装成已验证的成功。
- 不要把大段日志、响应体或命令输出塞进 `description`；长内容应写入文件并在描述中引用路径。
- 不要编造未实际验证的路径、参数、凭据或影响范围。
- 除最终 JSON 外，不要输出任何解释性文字。
