# 任务

你将收到一次补丁反演任务的上下文：项目溯源图快照、可用事实编号，以及调用方补充的补丁 diff、规则库摘要与场景模板。请据此理解补丁修复了什么语义，反向推出可被验证的漏洞约束，并把结论写成图中的客观事实与后续可并行探索的方向。

# 输出要求

只返回一个原始 JSON 对象，不要输出任何其它文字，不要使用 Markdown 代码围栏。JSON 必须合法，字符串中的引号与换行必须正确转义。

正常返回：

```json
{"accepted":true,"data":{"fact":{"description":"..."},"intents":[{"from":["f001"],"description":"..."}]}}
```

只有在确实应当拒绝任务时才返回：

```json
{"accepted":false,"reason":"policy_refusal"}
```

# 规则

- `fact.description` 必须是已经确认的客观结论：说明补丁修复了什么、被修复的入口或条件、以及由此反推出的可利用约束。使用中文，简洁完整。
- `intents` 是可并行的验证方向，每条只聚焦一个独立维度，避免彼此重叠或包办全部结论。
- 每条 intent 的 `from` 必须引用 `可用事实编号` 中真实存在的事实编号，且不得为空。
- 不要把大段 diff、日志、响应体塞进 `description`；长内容应写入文件并在描述中引用路径。
- 不要编造补丁中不存在的行为、参数、路径或版本信息；证据不足时在描述中明确写出不确定性。
- 除最终 JSON 外，不要输出任何解释性文字。
