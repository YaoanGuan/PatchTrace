# 任务

你将收到一张项目溯源图的 YAML 快照。图中的事实（facts）是已经确认的客观结论，意图（intents）是待验证的探索方向。图总是从一条或多条事实出发，通过一个意图产生新的事实。

请读懂整张图，判断两件事：

1. 现有事实是否已经足以证明目标达成；
2. 如果尚未达成，当前是否应当提出新的探索方向。

# 输出要求

只返回一个原始 JSON 对象，不要输出任何其它文字，不要使用 Markdown 代码围栏。JSON 必须合法，字符串中的引号与换行必须正确转义。

如果目标已经达成：

```json
{"accepted":true,"data":{"complete":{"from":["f001"],"description":"..."}}}
```

如果目标尚未达成、但应当提出新的探索方向：

```json
{"accepted":true,"data":{"intents":[{"from":["f001"],"description":"..."},{"from":["f002","f003"],"description":"..."}]}}
```

如果目标尚未达成、且当前不宜提出新的探索方向：

```json
{"accepted":true,"data":{}}
```

只有在确实应当拒绝任务时才返回：

```json
{"accepted":false,"reason":"policy_refusal"}
```

# 规则

- `complete.from` 必须引用 `可用事实编号` 中真实存在的事实编号；`complete.description` 必须说明为什么这些事实已经足以证明目标达成。
- 未达成目标时，先反思未达成的原因、是否偏离方向，以及是否需要一个纠正方向的意图。
- `开放意图` 是已经声明但尚未得出结论的意图。若 `开放意图` 为空，必须提出新的意图。
- 当已有开放意图较多、而当前图状态并未暴露出更高价值的方向时，可以不提出新意图，返回空 `data`。
- 提出的意图应是独立、可并行、互不重叠的高价值方向；聚焦核心判断与清晰方向，既不要过宽，也不要堆砌无关细节。一次通常不超过 5 条。
- 每条意图的 `from` 必须非空，且只能引用真实存在的事实编号。
- 不要编造图中不存在的事实、证据或结论。
- 除最终 JSON 外，不要输出任何解释性文字。
