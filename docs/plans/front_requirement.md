## 0. 一句话定义

把 Web 前端从“总脑调度 + 研究组协同”的旧叙事，切换为“**补丁反演 → 溯源图推理 → 沙箱实证 → 证据判决 → 审计回放**”的图驱动叙事；首页按模块顺序演示，后端每个迭代组件都在界面上有明确落点或明确缺口。

## 2. 设计原则

1. **图是主叙事**：首页首屏必须是图车道状态与模块演示，不再以总脑/研究组为主角。
2. **旧车道降级但保留**：旧实验室入口收进“兼容车道”，默认折叠；不删除后端能力。
3. **只展示真实数据**：项目数、节点计数、时间线全部来自 `/api/graph`；接口不可用时显示“未挂载”，不伪装成功。
4. **模块逐项对照**：每个 R* 在首页矩阵中有展示位、状态（已展示/部分展示/待接入）与入口。
5. **零新依赖**：沿用 React 18 + TypeScript + TailwindCSS + 既有 UI 组件；不引入图表库或路由库。
6. **中文界面、英文标识**：界面文案中文，代码标识与 API 字段保持英文。
7. **不改验收标准**：没有命令输出与截图证据，不把任务标记为完成。

## 3. 需求条目

### F1 首页范式切换（P0）

- 首页首屏改为“图驱动范式”：标题、副标题、状态徽标（图 API 可用/未挂载、图项目数）与主操作（进入溯源图）。
- 首屏不得出现“先由总脑接收”“总脑调度与研究组协同”等旧主编排文案。
- 验收：首页可见“补丁反演 · 溯源图推理 · 沙箱实证”，且不包含旧占位文案。

### F2 图项目实时总览（P0）

- 首页读取 `/api/graph/projects` 与最新项目的 `/snapshot`，展示事实/意图/提示/边/证据边/补丁档案/利用思路/验证观测/判决/规则命中计数。
- 项目列表不保证顺序，前端按 `created_at` 倒序取最新项目；展示“最近图项目 + 状态 + bootstrap 标记”。
- 图 API 不可用（非 JSON 响应）时显示明确原因，不展示 0 计数为“正常”。
- 提供“刷新图状态”按钮，重新拉取项目与最新快照（不做后台轮询，避免无谓请求）。
- 验收：隔离实例中可见项目标题与计数；截图文字包含“图 API 可用”。

### F3 演示路径（P0）

- 首页提供 6 步演示卡片，逐项对应：导入补丁（R7）→ 读图找缺口（R8）→ 认领意图（R3/R4）→ 沙箱实证（R9）→ 证据判决（R10）→ 导出与回放（R15）。
- 每步包含需求编号、说明与进入图谱的按钮。
- 验收：首页文字包含“图驱动演示路径”与 6 个步骤标题。

### F4 迭代组件矩阵（P0）

- 首页提供 R1–R16 对照矩阵，至少覆盖 M1–M9：
  - M1 补丁摄入与语义反演（R7）
  - M2 溯源图协议与租约（R3/R4）
  - M3 调度车道（R5/R6）
  - M4 沙箱实证（R9）
  - M5 证据闸门与反证（R10）
  - M6 规则回流（R11）
  - M7 人类意图注入（R12）
  - M8 审计与导出（R15）
  - M9 对照评测（R14）
- 每项展示状态：已展示 / 部分展示 / 待接入；部分与待接入必须写清缺口。
- 验收：首页文字包含“迭代组件 → 前端展示”。

### F5 旧车道降级（P0）

- “实验室/创建实验室”收进“兼容车道（旧总脑 / 研究组）”，默认折叠。
- 旧创建表单占位文案改为“兼容车道总任务（旧总脑模式，仅用于存量实验室）”。
- 实验室详情副标题标注“兼容车道”。
- 验收：首屏不出现实验室列表；展开后功能与改造前一致（列表、启动、停止、进入、删除、创建）。

### F6 品牌与文案（P1）

- 页面标题与顶栏改为 `PatchTrace · 补丁反演与溯源图推理`。
- 保留既有导航（数字人、报告模板、溯源图、MCP、Skills、设置）。
- 验收：服务返回的 HTML `<title>` 为 `PatchTrace`；顶栏文字正确。

### F7 图节点/边语义标签（P1）

- Fact 类型、Edge 类型、Intent 类型、Intent 状态显示中文语义标签，原始枚举保留在 `title` 提示中。
- 覆盖：`patch_profile/exploit_idea/constraint/observation/verdict/rule_hit/finding/gap`；`derive/support/refute/block/produce`；`open/claimed/running/resolved/concluded/refuted`。
- 验收：图面板中事实徽标显示“补丁档案/验证观测/判决”等，不再裸露英文枚举。

### F8 后端缺口补齐（P1，待后端）

| 缺口 | 需要的只读端点 | 前端落点 |
|---|---|---|
| 调度器运行态/车道模式 | `GET /api/graph/meta` → `{mode, config_path, dispatcher_running, workers}` | 首页车道徽标、M3 |
| 规则库版本与计数 | `GET /api/graph/projects/:id/rules` → `[{rule_id, version, confidence, hit_count, confirm_count}]` | M6、图面板新增“规则”区 |
| patcheval 指标 | `GET /api/eval/reports` 或静态产物路径 | M9 |
| Finding 报告 | `GET /api/graph/projects/:id/findings`（带 provenance） | 图面板“Finding”区、M8 |

> 本迭代只做前端；上述端点未实现前，界面如实标注“部分展示/待接入”，不得用 mock 数据冒充。
