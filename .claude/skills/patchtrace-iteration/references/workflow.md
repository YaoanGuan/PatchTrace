# PatchTrace 迭代工作流

来源：`docs/plans/requirement.md` §0、`docs/plans/task.md`「迭代执行提示词」、`docs/plans/todo.md` §1、§7。
本文件把三处的纪律合成一份可直接执行的操作手册。

## 1. 读取顺序

按固定顺序读，读完才动手：

1. `docs/plans/requirement.md`
   - 找到本次工作对应的 `R*`（§6）；
   - 读全局约束与红线（§7）：不推倒重来、单二进制 + SQLite、工厂尾部 append、分层不倒置、
     判定纪律、模型不可见、中文界面与提示词、验收证据；
   - 需要新增字段或改接口时，先看 §12「需求变更记录」。
2. `docs/plans/task.md`
   - 只读当前 Task 的 **Files / Interfaces / Steps**，以及其中引用的 `R*`；
   - 确认 Inputs/Outputs（谁产出了什么、名字与签名）；不知道的接口先问，不许猜；
   - 不改其他 Task 的文件。
3. `docs/plans/todo.md`
   - 看 §0「下一步动作」：本轮只做这一件；
   - 看 §2 总览与 §3/§4 的 checkbox，确认当前状态；
   - 看 §5 是否有阻塞。

执行提示词（来自 task.md，逐字执行）：

```text
按 docs/plans/task.md 执行 Task N。
1. 只读本 Task 的 Files / Interfaces / Steps，以及 requirement.md 对应 R*。
2. 不知道的接口先问，不许猜；不改其他 Task 的文件。
3. TDD：先写失败测试 → 跑失败 → 最小实现 → 跑通过 → 提交。
4. 完成后回写 docs/plans/todo.md，贴命令与真实输出。
5. 若发现计划与现实不符，停下并在 todo.md 记阻塞，不改验收标准。
```

## 2. TDD 步骤

每个 Task 的可执行步骤：

1. **先写失败测试**：落在 Task 声明的 `*_test.go` 或验收命令覆盖的位置。
2. **跑失败**：执行对应测试命令，确认失败原因正确（不是编译错误之外的假失败）。
3. **最小实现**：只实现让测试通过所需的代码；不顺带重构、不扩范围。
4. **跑通过**：再次执行同一命令；需要时追加 `-race`。
5. **全包回归**：按 Task 验收标准执行 `go test ./<pkg>/ -race` 或 `go build ./...`。
6. **提交**：提交信息描述本次 Task；提交前确认没有越界改动。
7. **回写 todo.md**：勾选 + 命令 + 真实输出 + 变更文件 + 下一步。

单测离线：不依赖真实 Docker / LLM；用 `t.TempDir`、fake driver、fake client、配置覆盖。
配置 DB 是进程单例：需要隔离时在首次配置访问前设置 `AIXVULN_DATA_DIR`。

## 3. todo 回写格式

每完成一步，按以下模板追加/替换（来自 todo.md §1.4）：

```text
- [x] Task N Step M
  证据：<命令> → <关键输出一行>
  变更：<文件列表>
  下一步：<两分钟内可执行的动作>
```

同时：

- 同步更新 `todo.md` §2 总览表的「状态 / 证据」；
- 状态取值只用 `未开始` / `进行中` / `阻塞` / `完成`；
- 未完成或无证据的项保留 `- [ ]`，并写清缺什么；
- 每轮结束留下三行：`已完成 / 证据 / 下一轮唯一动作`。

## 4. 验收证据要求

- **没有命令输出就不打勾**；不得用“应该通过”“已实现”代替输出。
- 证据 = 原样命令 + 关键输出（一行即可），例如：
  `grep -c '^---' .claude/skills/*/SKILL.md` → 每个文件 `2`；
  `go test ./graph/ -race` → `ok AIxVuln/graph`。
- 对照 task.md 的 Steps 与 Review Focus 检查遗漏。
- 检查越界：新增依赖、动 `factories[:7]` / `factories[:12]`、import `Web/` 均判不通过。
- 验收结论只允许两种：**通过** / **不通过（附最小复现）**。
- 不得修改验收标准来通过；发现计划与现实不符，停并记阻塞。

## 5. 阻塞上报格式

三行，禁止列清单（来自 todo.md §1.3）：

```text
- 现象：哪条命令、什么输出。
- 原因假设：最可能的一条，不列清单。
- 需要谁决策：问题一句话 + 两个选项。
```

同时写入 `todo.md` §5「当前阻塞」表。连续两轮同一 Task 无进展 → 必须记阻塞并换实现路径，
不得重复同一招。

## 6. 每轮收尾检查单

- [ ] 只做了 todo.md §0 指定的那一件事。
- [ ] 失败测试先于实现出现，且失败原因正确。
- [ ] 验收命令已执行，输出已原样回写。
- [ ] `todo.md` checkbox、§2 总览、§5 阻塞表已同步。
- [ ] 提交只包含本 Task 声明的文件。
- [ ] 给出了两分钟内可执行的下一轮唯一动作。
